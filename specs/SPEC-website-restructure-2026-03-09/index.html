    SPEC: Examark Website Restructure

    Status: draft Created: 2026-03-09 From Brainstorm: BRAINSTORM-website-restructure-2026-03-09.md Priority: High — improves discoverability for all three products

    Overview

    Restructure the examark documentation website to present CLI, Quarto Extension, and Claude Code Plugin as three distinct products with clear entry points. Replace the flat feature grid index with a three-pillar hero section, promote extensions to top-level navigation, rename "Tutorials" to "Cookbook" with task-oriented recipes, and expand the Claude Code Plugin page to comprehensive guide depth.

    Primary User Story

    As a statistics instructor discovering examark for the first time, I want to immediately understand which product fits my workflow (CLI-only, Quarto+R, or Claude-assisted), so that I can get started with the right tool in under 2 minutes.

    Acceptance Criteria

    • Index page has three distinct product sections above the feature grid
    • Each product section has: icon, 2-sentence description, install command, CTA button
    • Quarto Extension and Claude Code Plugin have top-level nav tabs (not nested under "Extensions")
    • "Tutorials" renamed to "Cookbook" with task-based organization
    • Each cookbook recipe follows standard format (TL;DR + Problem + Solution + Explanation + See Also)
    • Claude Code Plugin page expanded to ~400 lines with workflow guidance
    • mkdocs build --strict passes with 0 errors after all changes
    • All internal links updated (no broken references from file moves)

    Secondary User Stories

    As a Quarto/R instructor, I want the Quarto Extension prominently featured (not buried under "Extensions"), so that I find it immediately when exploring the site.

    As a Claude Code user, I want cookbook recipes showing how to author exams with Claude, so that I can learn the AI-assisted workflow through practical examples.

    As a returning user looking for a specific task, I want recipes organized by what I'm trying to do (not by tool), so that I find the answer quickly regardless of which tool I'm using.

    ## Three Ways to Use Examark

<div class="grid cards" markdown>

- :material-console:{ .lg .middle } **CLI Tool**

    ---

    Write exams in Markdown, convert to Canvas QTI packages. No coding required.

    ```bash
    npm install -g examark
    examark quiz.md -o quiz.qti.zip
    ```

    [:octicons-arrow-right-24: Getting Started](getting-started.md)

- :material-language-r:{ .lg .middle } **Quarto Extension**

    ---

    Author dynamic exams with R/Python code chunks. Randomized values, computed answers, auto-generated plots.

    ```bash
    quarto add Data-Wise/examark
    ```

    [:octicons-arrow-right-24: Quarto Guide](extensions/quarto.md)

- :material-robot:{ .lg .middle } **Claude Code Plugin**

    ---

    AI-assisted exam authoring with slash commands and auto-lint. Generate, validate, and iterate without leaving Claude.

    ```
    /exam:convert  /exam:check  /exam:preview
    ```

    [:octicons-arrow-right-24: Plugin Guide](extensions/claude-plugin.md)

</div>

    Open Questions

    1. Should docs/tutorials/ physically move to docs/cookbook/? — This breaks all existing external links. Alternative: keep files in tutorials/ but label as "Cookbook" in nav. Or add redirects.

    2. Should extensions/ directory restructure? — Currently extensions/quarto.md and extensions/claude-plugin.md. With top-level nav, the directory name is less visible. Could move to quarto.md and claude-plugin.md at docs root.

    3. How to handle the canvas-workflow.md split? — It's currently the most comprehensive tutorial. Splitting into recipes means some content becomes redundant. Need to decide: full split, or keep as a "guide" alongside shorter recipes?

    4. Visual Workflows page — Currently exists at top-level nav. Should it merge into Cookbook, or stay as a standalone visual overview?
